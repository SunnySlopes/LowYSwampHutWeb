      为什么用它
      
与桌面版同源的搜索内核

      
不是重新实现，也不是查表 —— 是同一套 C 代码编译成 WebAssembly。

    

    

      

        
        
同一套 C 内核

        
阶段 1 气候筛选与阶段 2 精确高度都由原项目 C 内核完成，与 Java 桌面版走同一条代码路径。

      

      

        
        
种子不出浏览器

        
所有计算在本地 WebAssembly 中完成，没有后端、没有上传、没有遥测。断网也能继续用。

      

      

        
        
精确的小屋 Y

        
Y 来自 footprint 全部 63 列的平均高度，并经过含水层灌满判定 —— 就是游戏里真实的建筑高度。

      

      

        
        
多版本 · 多世界

        
支持 26.2~26.3、1.19.x~26.1、1.18.x，以及普通、巨型生物群系、单群系（沼泽）三种世界。

      

    

  


  
  

    

      原理
      
三步，从种子到坐标

      
和桌面版完全相同的判定流程，只是在浏览器里跑。

    

    

      

        01
        
输入种子与范围

        
种子可以是任意 64 位整数。范围用「区域」表示：1 个区域 = 32 × 32 个区块 = 512 × 512 个方块。

      

      

        02
        
WASM 逐区域筛选

        
阶段 1 用气候、洞穴梯子、大陆性与含水层洪水度快速排除绝大多数区域；只有极少数候选进入阶段 2。

      

      

        03
        
精确高度与群系确认

        
阶段 2 计算 footprint 全部 63 列的平均高度，并确认群系确实是沼泽、没有被水灌满，最后输出 /tp 坐标。

      

    

    

      

        PHASE 1
        
气候与洞穴梯子

        
erosion / temperature / ridge / continentalness 与多层洞穴噪声，逐项淘汰候选区域。

      

      

        PHASE 2
        
63 列 footprint

        
三线性插值高度图 + 含水层判定 + 洞穴雕刻，得到真实的方块高度。Y 即小屋的真实 Y。

      

      

        BIOME
        
真实群系门

        
用 Minecraft 的多噪声群系参数树做最终判定，而不是只看气候近似值，避免假阳性。

      

    

  


  
  

    

      常见问题
      
你可能想知道

    

    

      

        结果里的 Y 是什么？
        
Y 是小屋 footprint 全部 63 列高度的平均值（整数除法，向零截断），也就是游戏里女巫小屋的真实建筑高度。它不是海平面，也不是近似值。

      

      

        为什么整图搜索仍然需要几分钟？
        
单种子在 HTTP 下会自动使用多个 Web Worker，但整图仍有 137 亿个区域，受 CPU 和内存带宽限制，无法像小范围那样瞬间完成；file:// 下浏览器不允许 Worker 读取本地脚本，会回退为单线程，明显更慢。

      

      

        线程数是怎么自动工作的？
        
HTTP 下页面会启动最多 12 个 Web Worker（移动端最多 4 个），每个 Worker 持有自己的 WASM 实例并扫描一段 Z 范围，因此不需要 SharedArrayBuffer / COOP-COEP。file:// 下无法启动这种 Worker，自动回退单线程；用 serve.ps1 / serve.sh 打开即可多线程。如果浏览器无法提供 CPU 核心数，或 Worker 创建/加载失败，也会自动回退单线程，不弹错误框。

      

      

        找不到小屋是正常的吗？
        
是。低 Y 女巫小屋非常稀有，整个 Minecraft 世界边界内通常也只有个位数到十几个。如果当前范围没有结果，可以换种子或扩大范围；高度筛选只提供 -40 及以下，-40 是最宽松的选项。

      

      

        会上传我的种子或数据吗？
        
不会。页面没有后端接口，所有计算在浏览器本地完成。种子只存在于当前页面内存中，刷新或关闭页面后即消失。

      

      

        支持哪些版本和世界类型？
        
支持 26.2~26.3（默认）、1.19.x~26.1、1.18.x；世界类型支持普通、巨型生物群系和单群系（沼泽）。版本会同时影响阶段 1 规则和群系参数表。

      

      

        可以在 macOS / Linux 上运行吗？
        
可以。网页和 WASM 与操作系统无关，Chrome / Edge / Firefox / Safari 都能运行。构建脚本提供 Windows 的 build.ps1 和 macOS / Linux 的 build.sh；serve.sh 用于本地服务器。
